## Section A

| Q | Answer | Why |
|---|---|---|
| **Q1** | **A** | Defaults are evaluated once, when the `def` statement executes. The object is stored on the function at `f.__defaults__`. D is the seductive wrong answer — the *binding* happens per call, the *evaluation* does not. |
| **Q2** | **C** | Only `def`, `class`, `lambda`, comprehensions and the module body create scopes. `for`, `if`, `while`, `try`, `with` do not — the loop variable outlives the loop. |
| **Q3** | **C** | The compiler sees `total = ...` in the body and marks `total` local for the *whole* function, including the earlier `print`. An unassigned local raises `UnboundLocalError`. |
| **Q4** | **C** | Everything after `*` is keyword-only. A and B pass extra positionals → `TypeError`. D puts a positional after a keyword argument → `SyntaxError`. |
| **Q5** | **B** | `*args` collects into a **tuple**, `**kwargs` into a **dict**. |

## Q6 — mutable default (12)

- **(a) 4 marks.** The list is created **once, when the `def` statement executes** (definition time,
  not first call). The reference is stored on the function object, at `add.__defaults__[0]`.
  *2 marks only* for "at definition time" without saying where it is stored.
- **(b) 4 marks.** Each call that omits `bucket` binds the local name `bucket` to that same one
  object. `bucket.append(v)` is a **method call that mutates the object in place**; it never rebinds
  the name. Since nothing ever creates a second list, every call sees the accumulated one.
  Must name append-mutates vs `=`-rebinds. *0 marks* for "the list is shared" alone.
- **(c) 4 marks.** `def add(v, bucket=None): if bucket is None: bucket = []`. `None` is safe because
  it is **immutable** — there is no operation that can change it, so one shared instance is
  unobservable. The `[]` now sits in the body and is therefore evaluated per call. Bonus-worthy:
  `is None` not `== None`, because identity comparison cannot be subverted by a custom `__eq__`.

---

## Q7 — global / nonlocal (12)

- **(a) 4 marks.** `global x` binds `x` in the **module** namespace when assigned inside a function.
  `nonlocal x` binds `x` in the **nearest enclosing function** scope (never module, never local).
  Both affect *assignment* only — reading an outer name needs neither.
- **(b) 4 marks.** Pass the running total in and return the new one:
  `def bump(total, v): return total + v`, with the caller holding `total = bump(total, v)`.
  Cost: one extra parameter, one extra assignment per call site, and the caller now owns the state.
  Must state the cost; a fix with no stated cost is half marks.
- **(c) 4 marks.** Any of: (i) two callers mutating the same module-level value get order-dependent
  results, and under threads a lost update with no exception; (ii) the function is now untestable in
  isolation — every test needs setup and teardown of module state and tests cannot run in parallel;
  (iii) the function's real signature is a lie, because its behaviour depends on inputs not in its
  parameter list. The underlying problem in every case: **hidden shared mutable state**, i.e. the
  function is not a function of its arguments.

## Q8 — pure functions (12)

- **(a) 3 marks.** Its return value is determined entirely by its arguments, and it changes nothing
  outside itself — no globals read or written, no I/O, no clock, no randomness, no mutation of the
  arguments. Same inputs, same output, every time.
- **(b) 6 marks, 2 each, mechanism required.** Any three of:
  - **Randomness** — weight init, shuffling, dropout, augmentation and `train_test_split` all draw
    from an RNG whose state is global and advances on every call.
  - **Mutation** — `fit()` writes the learned parameters θ into the model object it was called on;
    the object you passed in is not the object you get back.
  - **I/O and clock** — reads data from disk (which may have changed), writes checkpoints and logs,
    and early stopping can depend on wall-clock time.
  - **Hardware non-determinism** — GPU float reductions run in non-deterministic order, and floating
    point addition is not associative, so the same maths gives different low-order bits.
  - *"It uses randomness"* with no mechanism: 1 mark.
- **(c) 3 marks.** They run the change and see 0.91 vs 0.88 and conclude the change helped — when the
  run-to-run spread from seeds alone may be ±0.03. The measured difference is inside the noise floor,
  so the conclusion is unsupported and they will ship a change that did nothing (or harmed). The fix:
  fixed seeds, or n runs reported as mean ± std, and only believe deltas that clear the std.

## Q9 — closure late binding (14)

- **(a) 3 marks.** ```
  f1: 0.9
  f1: 0.9
  f1: 0.9
  ```
  All three print `f1`, not `acc`, `loss`, `f1`.
- **(b) 3 marks.** Late-binding closure. All three `report` functions close over the **same variable**
  `name`, not over three separate values.
- **(c) 5 marks.** `name` is a local of `make_reporters`, and `for` does **not** create a scope, so
  there is one `name` binding for the whole function. The inner functions capture the *variable* —
  a reference to that cell — not the value at the moment of definition. They read it when they are
  **called**, which is after the loop has finished and left `name` bound to `"f1"`.
  *Must state captured-variable-not-value AND read-at-call-time.* Either one alone: 2 marks.
- **(d) 3 marks.** Bind the value at definition time with a default argument:
  ```python
  def report(value, name=name):
      return f"{name}: {value}"
  ```
  The default is evaluated when the `def` executes — i.e. once per loop iteration — freezing that
  iteration's value. (`functools.partial` or a factory function that takes `name` as a parameter are
  equally correct.) Note the symmetry worth naming: this is the *same* definition-time-evaluation
  rule that is a footgun in Q6 and a tool here. The difference is that the captured object is
  immutable.

## Q10 — applied (20)

- **(a) 5 marks.** Three separate defects:
  1. `config={}` — mutable default. `config.setdefault("lr", 0.01)` **mutates the shared dict**, so
     the first call permanently writes `lr` into the default for every later call.
  2. `results=[]` — mutable default. One list accumulates across all five calls.
  3. The function both computes and accumulates — it has two responsibilities, which is why the two
     bugs are able to interact.
  *(Also creditable: the function returns the accumulator, so callers hold aliases to shared state,
  and any caller mutating the returned list corrupts every other caller's view.)*
- **(b) 4 marks.** Dataset five doesn't score best — it **looks** best because `results` is the one
  shared list. Call five returns a list of all five results, and whatever the colleague is reading
  (`results[-1]`, or "the longest list") is an artefact of accumulation order, not of model quality.
  The observation is a **measurement** bug, not a model result.
  *"Because the list is shared"* without connecting it to the false conclusion: 2 marks.

  **Full marks also require noticing the second-order hazard:** `setdefault` mutates the shared
  default dict, so `run.__defaults__[0]` is `{"lr": 0.01}` after the first call. In *this* code it
  writes the same value every time and is therefore silent — which is exactly what makes it
  dangerous. The moment anyone adds a key whose value depends on the dataset, or `train_model`
  mutates the dict it was handed, call five inherits call one's configuration and nothing reports it.
  A latent bug that is currently benign is still a defect; it fails the first time someone edits the
  function, and it fails silently.
- **(c) 5 marks.**
  ```python
  def run(dataset, config=None, *, seed=None):
      config = {"lr": 0.01, **(config or {})}   # new dict per call; caller's dict untouched
      return train_model(dataset, seed=seed, **config)
  ```
  Justifications required: `config=None` removes the shared-mutable default; building a **new** dict
  rather than calling `setdefault` means the caller's dict is never mutated; dropping `results`
  entirely makes accumulation the caller's job (`results = [run(d) for d in datasets]`), which is
  where it belongs; `*` makes `seed` keyword-only so it can never be passed positionally by accident;
  `seed` is an explicit parameter rather than a global RNG read, which is what makes the run
  reproducible. One mark per justification, not per line of code.
- **(d) 4 marks, 2 each.** Two of:
  - **Unseeded randomness** — init, shuffle and split all draw from the global RNG. Fix: accept an
    explicit `seed` and set it inside the function; never read the RNG state from module scope.
  - **Unversioned data** — "the dataset" may not be the same bytes as last week. Fix: hash the input
    and record the hash alongside the result.
  - **Unrecorded config** — the effective config was mutated at runtime and never written down. Fix:
    return or log the resolved config with every result.
  - **Unpinned dependencies** — a library minor version bump changes defaults. Fix: lockfile,
    recorded with the run.
  - Irreducible GPU non-determinism is a legitimate fifth, but only with the mitigation
    (n seeds, report mean ± std) attached.
- **(e) 2 marks.** Something with this shape: *"You are about to productionise a model chosen by a
  list-accumulation bug rather than by its score — the boilerplate costs you ten lines, and skipping
  it costs you shipping the wrong model and being unable to prove it afterwards."* Must connect the
  fix to the **decision at risk**, not to code aesthetics. Generic "it prevents bugs": 0 marks.
